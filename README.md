# Chat

Chat — небольшой самостоятельно развёртываемый мессенджер для прямых диалогов и
групповых переписок. Цель проекта — создать удобное веб-приложение и на его
практических задачах пройти полный цикл разработки backend на Go.

---

# Возможности

На текущий момент Chat поддерживает:

- локальный HTTP-сервер на `127.0.0.1:8080`;
- проверку работоспособности через `GET /health`;
- самостоятельную регистрацию, вход и выход;
- сессии в cookie и чтение собственного профиля;
- загрузку, замену, получение и удаление единственного фото профиля;
- создание прямого диалога по username, чтение переписки и списка своих переписок;
- создание единственной личной переписки с собой («Избранное»);
- ограничения частоты запросов регистрации и входа;
- корректную остановку HTTP-сервера с ожиданием активных запросов.

Также реализованы подключение к PostgreSQL и отдельная команда SQL-миграций.
Реализованы отправка текстовых сообщений и чтение истории страницами по 50 сообщений.
Групповые переписки и веб-интерфейс пока не реализованы.

Подробное текущее состояние и завершённые этапы находятся в
[`docs/ROADMAP.md`](docs/ROADMAP.md).

# Быстрый запуск

Backend:

Требуется Go 1.26.11 или новее. Из корня репозитория:
создайте `.env` из `.env-example`, если файла ещё нет, и заполните параметры PostgreSQL,
`STORAGE_DIR` и `MAX_PHOTO_SIZE` (см. конфигурацию ниже).

```powershell
docker compose --env-file .env -f docker/docker-compose.dev.yml up -d --wait postgres
go run ./cmd/migrate up
go run ./cmd/chat
```

Параметры PostgreSQL задаются в `.env`:
см. [настройку базы](docker/README.md#база-данных).
Перед запуском HTTP сервер проверяет связь с базой с таймаутом 5 секунд.

SQL-миграции применяются отдельно: `go run ./cmd/migrate up`.
Правила и проверка на тестовой базе — в
[`migrations/README.md`](migrations/README.md). Первая миграция создаёт таблицу `users`.

Проверка в другом терминале:

```powershell
curl.exe -i http://127.0.0.1:8080/health
```

Ожидаемый ответ: `200 OK` и `{"status":"ok"}`. Остановка — `Ctrl+C`.

# Эксплуатация

## Конфигурация

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `HTTP_ADDR` | `127.0.0.1:8080` | Адрес прослушивания в формате `host:port` |
| `SESSION_COOKIE_SECURE` | `true` | Передавать сессионную cookie только по HTTPS; для локального HTTP задайте `false` |
| `STORAGE_DIR` | Нет; обязательно | Каталог файлов; относительный путь считается от рабочей директории процесса |
| `MAX_PHOTO_SIZE` | Нет; обязательно | Максимальный размер загружаемого фото в байтах; положительное целое число |

Для IPv6 используйте скобки: `[::1]:8080`. Если значение отсутствует
или пустое, используется адрес по умолчанию. Формат и доступность адреса,
а также разрешение имени проверяются при открытии listener.
`0.0.0.0:8080` открывает сервер на всех IPv4-интерфейсах;
значение по умолчанию оставляет доступ только с локального компьютера.

Пример для PowerShell (настройка действует в текущем терминале):

```powershell
$env:HTTP_ADDR = "127.0.0.1:9090"
go run ./cmd/chat
```

Проверка: `curl.exe -i http://127.0.0.1:9090/health`.
Вернуть значение по умолчанию: `Remove-Item Env:\HTTP_ADDR`.
При запуске `run()` загружает `.env` в окружение процесса через `godotenv.Load`.
Файл читается из текущей рабочей директории.
Для локальной разработки запускайте его из корня проекта.

Приоритет: переменные окружения → `.env` → значения по умолчанию.
Отсутствие `.env` допустимо, ошибки чтения или синтаксиса прерывают запуск.
Уже заданные переменные окружения не перезаписываются, даже если они пустые.
Если итоговое значение `HTTP_ADDR` пустое, используется адрес по умолчанию.

Создание локального файла настроек (если `.env` ещё нет):

```powershell
Copy-Item .env-example .env
```

Пример содержимого `.env`:

```dotenv
HTTP_ADDR=127.0.0.1:8080
SESSION_COOKIE_SECURE=false
STORAGE_DIR=storage/files
MAX_PHOTO_SIZE=5242880
```

Параметры PostgreSQL также обязательны; полный шаблон находится в `.env-example`.
При доступе вне локального development-окружения необходим HTTPS.

`STORAGE_DIR` и `MAX_PHOTO_SIZE` не имеют значений по умолчанию;
пример выше задаёт лимит 5 MiB. Они обязательны и для команды миграций,
которая использует общую загрузку конфигурации, но не открывает хранилище.

## Файлы профиля

Приложение создаёт каталог `STORAGE_DIR` при запуске и хранит в нём
обработанные изображения. Каталог `storage/` исключён из Git и Docker build context.
Файлы выдаются через API с проверкой сессии; правила изображений и доступа —
в [`docs/DOMAIN_MODEL.md`](docs/DOMAIN_MODEL.md#фото-профиля), HTTP-контракт — в OpenAPI.

Для переноса или резервного копирования нужны и PostgreSQL, и файлы хранилища.
При удалении файлов без изменения БД запрос фото возвращает `404`.
Автоматической очистки файлов без ссылок в БД пока нет; такие файлы могут
остаться после аварийного завершения, неопределённого результата обновления БД
или ошибки удаления. Подробности порядка операций — в `docs/ARCHITECTURE.md`.

## Остановка

При `Ctrl+C` (или `SIGTERM` на Linux) сервер прекращает принимать новые
соединения и ожидает завершения активных запросов до 10 секунд. Если время
истекло, соединения закрываются принудительно, процесс завершается с кодом 1.

Для ручной проверки сигналов на Windows запускайте собранную программу напрямую:

```powershell
go build -o chat.exe ./cmd/chat
.\chat.exe
```

Нажмите `Ctrl+C` в том же терминале. При штатной остановке в логе появится
`HTTP server stopped`, код завершения — 0. Проверить код в PowerShell:
`$LASTEXITCODE`. Принудительное завершение процесса не гарантирует обработку сигналов.
Собранный `chat.exe` не добавляется в репозиторий.
