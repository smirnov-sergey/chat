# Roadmap

Roadmap показывает текущее состояние и только ближайший шаг. Следующий шаг
добавляется после завершения предыдущего.

## Текущее состояние

Работает локальный HTTP-сервер с `GET /health`, корректной остановкой
и конфигурацией через окружение и `.env`. Есть тесты HTTP, конфигурации
и жизненного цикла сервера. Есть Swagger UI и черновая документация.
Пользователи, переписки, хранение данных и веб-интерфейс ещё не реализованы.

**Активная глава: 2. PostgreSQL и хранение данных.**
**Ближайшая часть: PostgreSQL для локальной разработки.**

## Этап 1. Основа приложения

Результат: сервер можно запустить, проверить и штатно остановить.

- [x] Создать начальную документацию проекта.
- [x] Подготовить Docker-файлы и запуск Swagger UI.
  Docker-сборка приложения и база данных пока отсутствуют.
- [x] Создать Go-модуль, HTTP-сервер, `/health` и тесты маршрутов.
- [x] Добавить корректную остановку сервера и тесты жизненного цикла.
- [x] Добавить конфигурацию с дефолтами, окружением и `.env`, покрыть тестами.

## Этап 2. PostgreSQL и хранение данных

Результат: приложение подключается к PostgreSQL, схема базы версионируется,
тесты могут работать с отдельной тестовой базой.

- [ ] Добавить PostgreSQL в development Compose: учётные данные,
  постоянное хранение данных, проверка готовности и инструкции запуска.
- [ ] Подключить Go-приложение к PostgreSQL: выбрать и согласовать драйвер,
  добавить параметры подключения, проверку связи с таймаутом и закрытие пула
  после завершения HTTP-запросов. Проверить подключение и обработку ошибок тестами.
- [ ] Выбрать способ миграций и добавить команду применения миграций
  с учётом уже выполненных изменений. Проверить на отдельной базе.
- [ ] Подготовить изолированную БД для integration-тестов:
  применение миграций, очистку данных и воспроизводимую команду запуска.
  Тесты не должны изменять development-базу.

## Этап 3. Пользователь

Результат: пользователя можно создать и получить из базы на уровне Go-кода.
Публичного входа в приложение пока нет.

- [ ] Определить минимальные данные пользователя, правила их изменения
  и способ идентификации при входе. Зафиксировать модель в документации.
- [ ] Добавить Go-модель пользователя и проверки согласованных правил.
- [ ] Добавить миграцию и хранение пользователя: создание, получение
  и ограничения уникальности с integration-тестами.
- [ ] Реализовать прикладной сценарий создания пользователя:
  валидацию, обработку дубликатов и доменные ошибки.

## Этап 4. Регистрация и вход

Результат: пользователь регистрируется, входит, получает собственную
идентичность на сервере и выходит. Клиент не может выдать себя за другого пользователя.

- [ ] Определить правила регистрации, способ аутентификации и срок действия сессии.
- [ ] Реализовать безопасное хранение и проверку паролей
  в соответствии с выбранным способом входа.
- [ ] Добавить HTTP-регистрацию: ограничения ввода, контракт и тесты API.
- [ ] Реализовать вход и хранение сессий, обработку неверных учётных данных.
- [ ] Добавить проверку сессии на HTTP-границе и получение текущего пользователя.
- [ ] Реализовать выход, истечение и отзыв сессий.
- [ ] Добавить ограничения частоты попыток входа и регистрации,
  проверить cookie-настройки и защиту от CSRF, если используются cookies.

## Этап 5. Личная переписка

Результат: пользователь может начать личную переписку и увидеть свои переписки.

- [ ] Определить правила: два участника, повторное создание,
  переписка с собой и доступ посторонних пользователей.
- [ ] Добавить модель, миграции и хранение переписок и участников.
- [ ] Реализовать создание личной переписки с учётом повторных
  и одновременных запросов, добавить HTTP endpoint.
- [ ] Реализовать получение списка собственных переписок частями
  и получение отдельной переписки с проверкой доступа.

## Этап 6. Сообщения и история

Результат: участники отправляют текстовые сообщения и читают сохранённую историю.

- [ ] Определить правила текста, порядок сообщений и момент,
  когда сервер подтверждает успешную отправку.
- [ ] Добавить модель сообщения, миграцию и хранение.
- [ ] Реализовать отправку сообщения участником переписки через HTTP API.
- [ ] Реализовать историю с устойчивым порядком и пагинацией.
- [ ] Определить и реализовать поведение при повторной отправке
  после потери HTTP-ответа, чтобы повтор запроса не создавал дубликат.

## Этап 7. Минимальный веб-интерфейс

Результат: личной перепиской можно пользоваться через браузер.
До следующей главы новые данные можно получать явным обновлением.

- [ ] Выбрать frontend-инструменты, создать приложение и HTTP-клиент.
- [ ] Добавить регистрацию, вход и выход с обработкой ошибок и истечения сессии.
- [ ] Добавить список переписок и начало личной переписки.
- [ ] Добавить историю, отправку сообщения и состояния загрузки и ошибки.
- [ ] Добавить браузерный сценарий переписки двух пользователей.

## Этап 8. Получение сообщений в реальном времени

Результат: новые сообщения появляются без ручного обновления,
а после переподключения пропущенные данные можно восстановить.

- [ ] Выбрать транспорт, определить контракт событий и гарантии доставки.
- [ ] Реализовать аутентифицированное подключение и управление его жизненным циклом.
- [ ] Добавить отправку событий участникам после сохранения сообщения,
  ограниченные очереди и обработку медленных клиентов.
- [ ] Реализовать переподключение и восстановление истории
  без пропусков и дублирования отображаемых сообщений.
- [ ] Подключить события к интерфейсу и проверить сценарии отключений.

## Этап 9. Небольшие группы

Результат: несколько пользователей общаются в одной переписке.

- [ ] Определить правила группы: создание, роли, лимит участников,
  доступ к истории до вступления и после выхода.
- [ ] Реализовать создание группы и получение её участниками.
- [ ] Реализовать добавление участников с проверкой полномочий.
- [ ] Реализовать выход и удаление участника с отзывом доступа,
  включая уже открытые подключения для событий.
- [ ] Добавить групповые сценарии в интерфейс.

## Этап 10. Развёртывание и сопровождение

Результат: Chat можно воспроизводимо установить и использовать вне компьютера разработчика.
Необходимые проверки безопасности выполняются и в предыдущих главах,
а не откладываются до этой главы.

- [ ] Настроить CI: форматирование, unit- и integration-тесты,
  `go vet` и race detector в Linux. Можно выполнить раньше, когда готова тестовая БД.
- [ ] Подготовить production Docker-сборку и совместный запуск
  приложения, frontend и PostgreSQL.
- [ ] Настроить HTTPS и reverse proxy, проверить cookies,
  ограничения запросов и работу транспорта событий.
- [ ] Добавить необходимые для диагностики структурированные логи
  без паролей, токенов и содержимого личной переписки.
- [ ] Описать и проверить резервное копирование, восстановление
  базы и обновление приложения с миграциями.
- [ ] Развернуть приложение и провести сквозную проверку:
  вход, личная и групповая переписка, переподключение и перезапуск сервера.

## Границы плана

В этот план не входят вложения, звонки, каналы, боты, мобильные приложения,
сквозное шифрование, статусы прочтения и поиск по сообщениям.
Их не реализуем заранее. План не является обязательством вместить все
главы в полгода: объём корректируется по фактическому темпу и пониманию материала.
Первый полезный результат — личная переписка через веб-интерфейс;
следующие результаты — доставка событий, группы и развёртывание.
